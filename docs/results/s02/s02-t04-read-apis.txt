  Balances    After golden O1-O7, every account matches the D01-9 expected balances on BOTH presented_minor (the
              account's normal side) and signed_minor (as stored). as_of_seq equals the entity's changelog row count.
              driver:D1 payable reports normal_side CREDIT. An unknown entity is 404 entity_not_found; a malformed ID
              is 400 invalid_entity_id.
  Changelog   Paging with limit=7 over 25 applied orders returns every row exactly once, in sequence order, starting at
              seq 1, with no repeats across pages. Every row carries a UUID order_id and a non-blank source.system and
              source.idempotency_key - that join to applied_orders is the M6 (a) link. A request past the last sequence
              returns an empty page with no cursor, not a 404. limit=0, limit=501, limit=abc, after_seq=-1 and

TWO FINDINGS, BOTH IN THE TESTS RATHER THAN THE SERVICE
  1. Twelve API tests failed at context startup: "No qualifying bean ... 'restClientBuilder'". Boot 4.1 splits
     auto-configuration into modules and ledger-service carries no RestClient client module, so no RestClient.Builder
     bean exists. The tests do not need one; they now call RestClient.create(baseUrl). No production change.
  2. anEncodedColonAddressesTheSameEntity() then failed with 400, and the problem body showed the request path as
     /v1/entities/rider%253AR1/balances. RestClient's String uri(...) overload treats its argument as a URI template and
     encoded the percent sign itself, so the test had never sent a percent-encoded colon at all. Passing a java.net.URI
     sends %3A unchanged, and the endpoint then resolves it to the same entity as the literal colon. The capability was
     unverified rather than broken, and is now genuinely verified.

SERIALIZATION DECISION, CHECKED RATHER THAN ASSUMED
  The API is snake_case throughout. Instead of annotating every response record, ledger-service sets
  spring.jackson.property-naming-strategy: SNAKE_CASE once. Every schema in the specification sets
  "additionalProperties": false, so LedgerOpenApiContractIT checks the serialized field names one by one; a naming slip
  fails the build. The contract tests passing is what confirms the setting works under Boot 4.1 with Jackson 3.
