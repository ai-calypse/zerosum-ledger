AUTH (D03-4)
  No token -> 401 unauthorized. Reader token on create -> 403 forbidden. Writer token on reads -> 200, the recorded
  hierarchy. Ledger read endpoints: 401 without a token, 401 with an unknown token, 200 with reader, writer or admin.
  Tokens are compared with MessageDigest.isEqual against every configured token, so timing cannot reveal match position.

STRICT REQUEST PARSING - THREE FAILED ATTEMPTS BEFORE IT WORKED, RECORDED BECAUSE THE FAILURE MODE MATTERS
  The requirement is that unknown fields, duplicate keys and a float where an integer amount belongs are all REJECTED.
  Attempt 1: spring.jackson.parser.strict-duplicate-detection. Boot 4.1 has no `parser` map, so the key bound to
             nothing and the service silently accepted duplicate keys. Tests: 3 bodies accepted with 201.
  Attempt 2: corrected to spring.jackson.read.* (StreamReadFeature does bind there). Still 3 bodies accepted: the
             properties were not reaching the HTTP message converter's mapper.
  Attempt 3: a JsonMapperBuilderCustomizer bean, which IS the hook Boot builds its JsonMapper from. Correct, but I put
             the @PostConstruct self-check in the same class, so the class injected the mapper built from its own
             customizer. Spring rejected the circular reference and the context failed to load - all 15 tests failed.
  Final:     the customizer and the self-check are separate beans. 15/15 green, including all three rejection cases.

  A startup self-check now asserts the mapper genuinely refuses those three inputs. Silent misconfiguration is the
  real hazard here: for two attempts the service looked correctly configured and accepted malformed money orders. If a
  future Boot upgrade moves the hook again, the service fails at boot with a named reason instead.

ONE API GAP FOUND BY THE SCHEMA CHECK
  Fetched orders omitted `metadata`, which the D01-8 contract requires (and additionalProperties: false means nothing
  else can stand in for it). The response now carries it as an object, parsed back from the canonical text the store
  holds.
